## Evidence and reports

Compatibility declarations identify documented prerequisites and known blockers; they do not certify that a tool works. The compatibility report deliberately keeps catalog installability, PATH discovery, source metadata, smoke tests, and device validation separate. Do not publish a report as proof of tool functionality unless the relevant tool was actually tested and the device/tool details are recorded.

Physical-device reports may include architecture, paths, installed runtime versions, and other local system details. Sanitize these details before public issue reports. Never attach API keys, session tokens, private targets, captured traffic, or unredacted assessment output.
